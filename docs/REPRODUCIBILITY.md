# Reproducibility and data provenance

## Scope of the public repository

This repository contains preprocessing, training, evaluation, and inference code. Historical run exports, analysis figures, reports, and the presentation are in versioned local archives outside this repository. It does **not** contain the raw or processed audio, the final Hugging Face `DatasetDict`, pretrained weights, fine-tuned checkpoints, or an MLflow artifact store. A fresh clone can run baseline inference after downloading dependencies and a model; it cannot independently reproduce the reported fine-tuning scores without those inputs.

## Current combined-catalog Whisper Small workflow

[Whisper Small](../notebook/whisper-small/README.md) uses the combined catalog built by `scripts/data/build_combined_catalog.py`, rather than the historical `DatasetDict` below. The 2026-11-09 snapshot has 37,296 curated clips / 94.190 hours, including 26,465 labeled clips / 64.147 hours and 10,831 unlabeled VOA clips / 30.043 hours. Training uses only the curated labeled training duration view and excludes labels beyond the model limit; validation and five named tests remain held out. Full dataset inventory hours are not supervised training hours.

The notebook records manifest hashes, resolved model commit, package versions, hyperparameters, accepted/rejected counts, baseline/final validation scores, and per-test predictions and metrics. Preserve those files with the repository commit and original catalog/audio. It reads file-backed and embedded audio without creating a duplicate waveform cache. Local outputs are ignored by Git. No full training or new quality score is established by updating this recipe.

The catalog audit documents YODAS video overlap and uncertain UCSY speaker identities; do not describe these splits as speaker/video-disjoint. Obtain local ASR/UCSY inputs separately and confirm their usage permissions. A clone includes the [catalog report](../combined/myanmar_asr_all/README.md), not the recordings or generated CSVs. See [data preparation](../scripts/data/README.md) for regeneration.

## Dataset snapshots

The archived project report describes a later corpus of **22,705 examples / about 54.2 hours** after cleaning and speed augmentation. The archived `viz/dataset_analysis/dataset_stats.json` belongs to an earlier **12,299-example / about 24.34-hour** snapshot (11,661 train, 319 validation, 319 test). These figures must not be treated as the same dataset release. The final corpus manifest and hashes are not present, so the 54.2-hour count is a reported result rather than a count independently verifiable from this repository.

Sources used by the data scripts:

| Source | Upstream record | License shown by upstream |
| --- | --- | --- |
| FLEURS, Burmese `my_mm` | [Google FLEURS](https://huggingface.co/datasets/google/fleurs) | CC BY 4.0 |
| Burmese speech corpus | [OpenSLR 80](https://openslr.org/80/) | CC BY-SA 4.0 |
| YODAS Burmese | [ESPnet YODAS](https://huggingface.co/datasets/espnet/yodas) | CC BY 3.0 |

Check each upstream license and attribution requirement before distributing a derived dataset. The MIT license in this repository covers its original code and documentation, not third-party recordings or model weights.

## Results and metric evidence

The test values in the README are recorded as constants in [`scripts/viz/presentation_charts.py`](../scripts/viz/presentation_charts.py) for the thesis figures. The archived `viz/mlflow_metrics.json` provides validation curves and training runtimes, including Whisper Turbo's best validation WER 54.49% and CER 36.00%. It does not include test predictions or transcripts. Test metrics should therefore be read as **reported experiment results**, not results regenerated by this clone.

WER and CER are computed with Hugging Face `evaluate` in the training scripts. Burmese word spacing makes WER sensitive to tokenization and normalization. Any new comparison should state its exact text normalization and segmentation policy, as well as the evaluation split.

## Reproducing an experiment

1. Obtain each upstream dataset under its own license and use the scripts in `scripts/data/` to build a `DatasetDict` containing `train`, `validation`, and `test` splits with `audio` and `sentence` columns.
2. Keep speaker and source separation between training and evaluation. Save the dataset revision, split counts, duration totals, and a manifest checksum alongside the run.
3. Record the exact pretrained model revision and Python package versions. The original 24 GB training setup is described in the locally archived training progress report; the separate [K80 decision](CentOS7_K80_Compatibility_Decision.md) is a compatibility path and has not reproduced the original scores.
4. Run the chosen script in `scripts/training/` with explicit `--dataset_path`, `--model_id`, and `--output_dir` arguments. Preserve the generated checkpoints, logs, and test result JSON for audit.
5. Report test WER/CER only after selecting the checkpoint on validation data. Include predictions or a checksum of the evaluation output when publishing new results.

The released scripts contain historical experiment paths and external service assumptions. They are research artifacts rather than a one-command reconstruction of the thesis environment.
